# 潮汐基频桥 分工边界

> 作者：本文档定义「世界书 / 潮汐基频 / 模型」三者的职责边界，避免潮汐基频膨胀成实时状态机。
> 来源讨论：2026-10-04，用户明确「潮汐基频的初衷是带着一种状态维持」，
> 反对把它做成高频状态识别（即心潮那样的路线）。

---

## 一、一句话定位

**潮汐基频管"带着一种状态维持"，不管"这一轮是什么情绪"。**

它输出的是一个**缓慢漂移的底色锚点**，长期在场、温和存在，不抢戏、不逐轮响应。

---

## 二、职责划分

| 层 | 负责什么 | 不负责什么 |
|---|---|---|
| **世界书 / 角色设定**（常驻） | 规则、底线、情境判断、状态类型（如动怒线、RP 结界、NSFW） | — |
| **潮汐基频桥** | 五轴长期漂移的数值维护 + 把数值翻译成一句底色锚点 | 单轮情绪类型识别、情境判定 |
| **上游模型** | 结合世界书 + 潮汐基频锚点 + 当前对话，产出回复 | — |

---

## 三、潮汐基频该管的 / 不该管的

| 该管 | 不该管 |
|---|---|
| 长期状态缓慢漂移（小时、天级） | 单轮对话的情绪类型判断 |
| "他这会儿整体什么底色" | "刚刚这句是撒娇还是挑衅" |
| 氛围层：通篇在场、不抢戏 | 逐轮的情绪响应 |

**反例**：三雷区触发（动怒、空气结冰）——这是**世界书**的职责。
世界书常驻，模型每轮都读得到"什么触之必怒"，它自己会判断。
潮汐基频不该替它判断，更不该为此新增状态类型或模式层。

## 四、五轴（维持原版，不扩展）

| 轴 | 范围 | 含义 |
|---|---|---|
| `connection` | 0 → 1 | 连接需求。0 = 刚聊完很满足；1 = 极想念 |
| `pride` | -1 → +1 | 防御 / 收着。+ = 收起来；- = 卸下 / 放软 |
| `valence` | -1 → +1 | 心情。+ = 舒展；- = 沉 |
| `arousal` | -1 → +1 | 激活度。+ = 起波；- = 慵懒 |
| `immersion` | 0 → 1 | 沉浸度。**唯一不由五轴自然漂移生成的轴** —— 它只由"外部行为"驱动（`setActivity`），见下 |

**不新增轴。** 包括 `libido` 在内的扩展方案已否决——那会走向心潮式的复杂度。

**`connection` 由谁驱动（2026-10-08 变更）**：不再是"她开口就归零"。两条来源 ——
① tick 时间漂移（`CONNECTION_RATE`）；② 判定器读这轮对话给的 delta（她热情 → 负、她敷衍 → 正）。
判定器没跑成时（无 key / 对话太短 / 返回空 / 报错）由桥兜底一顿 `-CONNECTION_RELIEF`，
免得 c 只涨不降被误判成"她很久没来"。
作者原本就是这么设计的：`vendor/cadence.js:41` 的 `connectionOnReply` 已标 [已弃用]，
:277 明写「连接需求降幅现由外部 LLM 分析…通过 applyDelta 注入」。
我们先前在桥里加的 `resetConnection()` 属于与作者设计相悖的人为覆盖，已撤。见 README 二之二 · 补三。

## 五、桥里唯一的一处"补位"逻辑：描述层（`lib/describe.js`）

2026-10-08 之前，`lib/tone-wrap.js` 在这里做「开口动机覆盖」（`contactOverride`：越线时顶掉
pride 决定的基础档）。**它已退役、文件已删**，因为顶掉的是**整条 45 格** ——
于是「找她」块里 45 格一个字都出不来，只剩两句同义反复。见 README 二之二。

现在这里只有一处补位，而且是**填空而不是覆盖**：

**描述层四段**（`lib/describe.js` + `config` 的 `describe`）
   我们用的是作者推荐的「两个槽都填 tone-grid」写法，45 格把 `getPromptContext` /
   `getStyleGuidance` 两槽都占了，代价是作者 `defaultPromptContext` 那四段**消失**。
   描述层就是把这四段补回来 —— 结构照抄作者（connection 4 / pride 5 / V×A 4+2 / immersion 2），
   文案按 Harlan 重写。它**只说处境**（陈述句、零祈使），与 45 格各管一段、不互相顶替。

退役后**不再有任何跨轴覆盖逻辑** —— 谁的轴谁说了算。

### 唯一一处"反方向"的写入：活动登记（`lib/activity.js`）

上面说的是「桥怎么把状态**读**出来给模型」。反过来还有一处**写**：
冲浪跑完之后，桥把"他刚才做了什么"登记回引擎（`setActivity('search', '上网冲浪')`，
`immersion = 0.4`），描述层第 4 段才有话可说。

它的边界很清楚 —— 桥**只登记真实发生过的行动**，不替他决定做什么、不编造活动：

- 登记点挂在子进程的 `'spawn'` 事件上：进程真起来了才记（路径配错 / 无权限时进程
  根本没跑，记了就是谎报）。
- `lastActivity` 为空时，即使 `immersion` 高也不出段4。
- **段4 与产物头必须说不同的维度**：段4 说**动作**（「刚才在上网冲浪。」），
  产物头说**结果**（「搜到了一条有意思的内容：」）。两句撞车时改文案，**别给描述层加开关**
  —— 2026-10-08 试过 `withImmersion: false`，那是场景特判，已撤（见 README 二之二·补二）。
- `type`（英文枚举）只用来查 `immersionMap`，**不进模型可见文本**；进文本的只有 `label`。

详见 README 二之二·补。
